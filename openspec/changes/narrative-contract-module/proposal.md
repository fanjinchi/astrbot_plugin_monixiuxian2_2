# narrative-contract-module

## Why

叙事文案的「模板插值变量契约」在仓内被实现了至少三份，且解析器互相不一致：

1. 运行时校验：`utils/narrative_text.py:111-124` 的 `extract_template_vars` 用 `string.Formatter` 解析；
2. 同步闸门：`scripts/sync_copy_variants_to_config.py:141-143` 的 `_template_vars` 是 regex「镜像」（`re.findall(r"\{(\w+)", ...)`），在转义花括号、`{x[0]}` 嵌套字段、`{var:spec}` 格式符上与 `string.Formatter` 语义发散——闸门放行的稿子可能在加载校验处被拒，反之亦然，二者只能靠日志事后发现；
3. lint 闸门：`design_docs/content-design/lint_narrative.py:117` 的 `_WHITELIST_VAR_RE` 又是第三个 regex。

同时 `config_manager.py:23-28` 为做加载校验**私有** import 了 `narrative_text` 的内部符号（`_NARRATIVE_ROUTES`、`_iter_scene_entries`），跨模块泄漏实现细节。

文案内容本身也存于三处：`design_docs/content-design/copy_variants.csv`（设计真源，AGENTS.md §15 唯一合法内容入口）、`config/narrative_config.json`（38 KB，已入库、由同步脚本写入——**实际上已是生成物但无声明**）、`data/narrative_defaults/*.py`（514 行手维护 Python 字面量，作为空池回退）。同步脚本只更新 JSON，内嵌默认靠手工与契约对齐（仅靠 `tests/test_narrative_config.py` 的「内嵌默认全量符合契约」场景兜底），三份拷贝可静默漂移。

## What Changes

- 新增单一深模块 `utils/narrative_contract.py`，导出公共 API：`used_vars(template)`（唯一模板变量解析器，`string.Formatter` 实现）、`validate_scene(section, scene, value, declared)`（吸收 `config_manager._check_narrative_scene` 的全部形态分支：单模板/扁平池/分桶池/route 标注/双槽 panel）、`iter_scene_entries(value)`（吸收 `_iter_scene_entries`）、`NARRATIVE_BUCKET_KEYS`/`NARRATIVE_ROUTES` 常量。模块同时支持包内 import 与按路径独立加载（沿用 `utils/narrative_text.py:47-71` 的 standalone trick，供 managers 测试 shim 与脚本复用）。
- `utils/narrative_text.py` 的 `extract_template_vars` 变为对 `narrative_contract.used_vars` 的薄包装（保留公开名，避免连锁改动），池迭代改从 contract 导入；渲染主路径（`render_narrative` :303-334 的 config→内嵌默认回退链）行为不变。
- `config_manager.py:23-28` 改从 `narrative_contract` 公共 API 导入；`_validate_narrative_config`/`_check_narrative_scene`（:521-632）委托给 `validate_scene`，日志文案与回退语义保持现状。
- `scripts/sync_copy_variants_to_config.py:141-143` 删除 regex `_template_vars`，改用 `narrative_contract.used_vars`（按路径加载 contract 模块，与 :103-116 加载 narrative_defaults 同款手法）。
- 文案管线显式化：`config/narrative_config.json` 标注为生成物（文件头注释「GENERATED by scripts/sync_copy_variants_to_config.py — do not hand-edit」）；`data/narrative_defaults/*.py` 改为由同步脚本 `--emit-defaults` 从通过双闸门后的 config 池再生成（冻结快照，语义=「基线时的最小回退」），并新增漂移检查（`--check-defaults` 或 pytest 场景：重新生成输出与入库快照逐字一致），消灭手维护字面量。
- `scripts/import_copy_variants.py`（剧本册→CSV，无模板解析）与 `lint_narrative.py`（design_docs 侧白名单 regex）不在本次合并范围，但在 design.md Non-Goals 中登记跟进方向。

## Impact

- **代码**：新增 `utils/narrative_contract.py`（深模块，吸收 3 处实现）；`utils/narrative_text.py`（瘦身：删解析器与池迭代实现）、`config_manager.py`（:23-28 公共导入、:521-632 校验委托）、`scripts/sync_copy_variants_to_config.py`（+约 60 行生成/检查逻辑，-10 行 regex 镜像）。
- **生成物**：`config/narrative_config.json`（加 GENERATED 头注释）；`data/narrative_defaults/*.py`（内容快照重排为生成格式，**运行时不差分**——键与池内容与现状一致）。
- **测试**：`tests/test_narrative_config.py` 补 contract 单测（解析器边界：转义 `{{}}`、`{var:spec}`、嵌套字段根提取；`validate_scene` 全形态）；新增 defaults 快照漂移检查场景。
- **文档**：`AGENTS.md` §架构速览/§15 如提及 narrative_defaults 手维护性质需改述为「生成物」；`openspec/specs/narrative-text-config/spec.md` 载体括注同步；`design_docs/README.md` 如登记 defaults 为手维护资料需改注。
- **无**数据库迁移、无对外玩法行为变化；脚本双闸门（预算 + lint）继续生效。
