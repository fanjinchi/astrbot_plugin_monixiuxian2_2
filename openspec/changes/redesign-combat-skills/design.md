# 设计：数值、战斗与技能系统重设计（草案 v0.1）

> 本草案由与维护者讨论形成，记录**已确认的决策**与**待定的开放问题**。
> 现状基线：`design_docs/current-design-report.md`；设计参考：`design_docs/mybrute/`、`design_docs/qpet-daledou/`。

## Context

- **现状问题**：战斗为纯 ATK 对撞（`atk = exp // 10`），五维属性、MP、灵修/体修差异在实战中不起作用；功法只是被动装备，配装无策略深度（详见现状报告 §4.5）。
- **参考依据**：My Brute 与 Q宠大乐斗早期版本（同源设计，后者底层玩法借鉴前者）：
  - 全自动战斗 + 随机成长 build + 被动/概率触发技能配装
  - 主属性分工明确（伤害 / 闪避 / 出手速度 / 生存）
  - 技能分层：常驻属性被动 → 概率触发技 → 每局限次大招 → 极小概率戏剧技
- **讨论结论**：本项目的重设计方向与上述模式对齐（维护者已确认战斗交互与两款参考一致）。

## Goals / Non-Goals

**Goals:**

- 全自动回合制战斗：战中零操作，胜负由配装 + 对手选择 + 随机判定链决定，战报具备叙事性
- 属性框架向参考游戏靠拢：分工明确的主属性，来源改为「境界基础 + 随机成长」
- 十进制境界体系：等级数字直接编码大境界与小阶段
- 装备驱动技能：心法 = 属性被动 + 配套功法池；功法 = 触发技 + 大招；武器 = 触发技
- 随机成长获取循环：闭关概率领悟功法、突破小概率获得功法

**Non-Goals:**

- 战中手动操作 / 主动施放技能（明确排除，保持纯自动）
- 修炼升级曲线的具体数值（另立议题规划）
- 经济系统（银行/商店/悬赏/洞天等）重构
- Q宠大乐斗现行版 / 大乐斗2 的复杂系统（佣兵、门派、奥义等）

## Decisions

### D1 全自动回合制战斗

- 玩家战中**零操作**；战前决策 = 配装（心法/功法/武器）+ 选择对手。
- 战报按判定链依次结算，产生可读叙事：命中/闪避 → 格挡 → 反击 → 减伤 → 伤害，穿插技能触发事件（连击/控制/大招等）。
- 参考：`design_docs/mybrute/wiki-combat.md`（社区推导伤害公式）、`design_docs/qpet-daledou/battle-mechanics.md`（速度出手分配）。

### D2 属性框架：向参考游戏靠拢（已与维护者确认）

- **四主属性**：**伤害 / 身法 / 迅捷 / 气血**（对标 My Brute 四属性；「力道」直接命名为「伤害」，直白易懂）。
- **防御不是主属性**：由装备护甲值（加法减伤，参考 Muxxu 公式 `−A`）与技能（格挡/减伤被动）提供。
- **精神力/MP 直接废弃**，不再作为战斗属性存在。
- 属性来源 = **境界基础值 + 随机成长**，取代当前「一切从 exp 派生」（HP=exp//2、ATK=exp//10 的公式全部废弃）。
- **同一属性池**：所有玩家共用同一套主属性，不按路线分叉属性框架（路线差异见 D5）。

### D3 十进制境界体系

- 每个大境界 10 个小阶：**初期 + 一阶~九阶**。
- 等级数字编码：**十位 = 大境界序号，个位 = 小阶段**（0=初期，1-9=一阶~九阶）。
- 映射示例（已与维护者确认）：练气一阶~九阶 = 1-9（练气无「初期」，新玩家从 level 1 起步）；筑基初期 = 10，筑基一阶~九阶 = 11-19；金丹初期 = 20，依此类推。
- 修炼升级曲线（每小阶所需修为）需随新体系重新规划 → 另立议题（Open Questions）。

### D4 技能挂载与获取（配装玩法核心）

| 装备位 | 携带内容 | 类比参考 |
|---|---|---|
| **心法** | 属性被动（常驻加成）+ **配套功法列表**（决定可领悟的功法池） | My Brute 属性被动技（Herculean Strength 等）/ Q宠第一排属性技 |
| **功法** | 随机触发技能 + **大招**（每局限次，类 My Brute Super） | 反击/连击/控制触发技 + Hammer/Deluge 类大招 |
| **武器** | 仅随机触发技能 | 武器特效标签（Multi hit/Counter/Disarm） |

- **获取机制（随机成长循环，Q宠模式——已与维护者确认）**（概率均为初值，写入 config 可调）：
  1. **突破成功** → 随机一项主属性 **+N**（属性奖励仅在突破成功时获得）+ **20%** 概率判定功法领悟；
  2. **突破失败** → 保留现有掉修为惩罚 + **10%** 概率判定功法领悟（成功概率的一半；「破而后立」安慰机制兼作软保底）；
  3. **闭关领悟**：闭关结算时按时长判定——每满 2 小时一次判定，每次 **15%**（需装备心法）。
- **领悟概率系数（已确认）**：配套列表中每个功法带「领悟概率系数」，实际领悟概率 = 基础概率 × 系数，用于为不同功法设置领悟难度（稀有功法系数低）。
- **功法来源池（已确认）**：
  - 有心法装备时：从该心法的「配套功法列表」中随机（按领悟概率系数加权）；
  - **通用功法池**：领悟成功时 **5%** 来自通用池；无装备心法时突破渠道按 **3%** 独立判定通用池（新玩家保底入口）；
  - **通用池仅挂突破渠道**；**闭关领悟只从心法配套列表抽取**；
  - 玩家设定的「修习目标」功法加入领悟随机池（见 D7）。
- 技能分层设计原则：常驻属性被动（稳定提升）> 概率触发技（翻盘）> 每局限次大招（高潮）> 极小概率戏剧技（话题性，如 Q宠「装死」「神来一击」）。
- **大招限次（已确认）**：每本功法的大招每场战斗最多触发一次；装备多本功法时多个大招各自独立判定。
- **功法槽位（已确认）**：保持 3 个槽位；重复获得同名功法时自动升星强化（提升触发概率/效果），参考 Q宠武器升星。

### D5 灵修/体修：路线差异落在装备池，而非属性池（已与维护者确认）
- 灵修/体修身份保留，但**不区分属性框架**（同一属性池）。
- 两条路线**分别设计不同的心法 / 功法 / 武器**（各自专属装备池，心法配套功法列表按路线设计）。
- **部分功法/武器双方都可学习，但加成倍率不一样**（同一件装备在两路线下数值不同）。

### D6 战斗结算骨架（已与维护者确认）

- **出手权**：每次行动前按迅捷加权随机判定：`P(甲出手) = 迅捷甲 / (迅捷甲 + 迅捷乙)`；每次出手 = 一次攻击；总行动次数封顶（如 200 次），超限判平局。
- **伤害公式（Muxxu 式，装备驱动）**：`伤害 = floor((武器基础伤害 + 伤害属性 × 武器系数K) × 技能倍率 × 随机浮动 − 护甲)`，下限 1；大武器 K 高（吃属性）、小武器 K 低但基础伤害稳（新手友好）；空手有保底基础伤害。
- **判定链（每次出手依次）**：出手权 → 闪避（身法差，闪避率设上限如 50%）→ 格挡（装备/技能）→ 暴击（×1.5）→ 触发技（连击/反击/控制/追击）→ 大招（每场一次）→ 结算伤害。
- **战报输出（聊天场景适配，已确认）**：不逐条实时发送，**若干条结算合并为一条消息输出；合并条数用户可配置，默认 10 条**。

### D7 功法：拥有与领悟分离（已与维护者确认）

- 功法可通过**商店购买 / 打怪掉落 / 领悟**获得（拥有形态为物品，延续现阶段设定）。
- 玩家拥有的每个功法增加「**是否已领悟**」字段；**只有已领悟的功法才能装备使用**。
- 玩家可将一个已拥有但未领悟的功法设为「**修习目标**」，修习目标加入领悟随机池（即可通过闭关/突破的领悟判定定向修习）。

## Risks / Trade-offs

- [属性重构推翻现有五维与装备词条] → 维护者已决定不做存量迁移，旧数据直接废弃（清档式更新），无需映射方案
- [随机成长带来挫败感（roll 不到好功法）] → 「破而后立」（突破失败 10% 领悟）+ 修习目标定向修习 + 通用池保底入口，三层缓冲
- [十进制境界与现有 36 境界 `level_config.json` 不兼容] → 旧配置整体重写，不做 `level_index` 映射
- [纯自动战斗缺乏操作感] → 靠战报叙事与配装深度补偿（两款参考游戏已验证该模式成立）

## Migration Plan

**不做存量迁移**：维护者已确认旧数据直接废弃（清档式更新），不编写 `level_index` / 旧属性映射。

- `players` 表按新属性框架重构（四主属性 + 功法领悟字段），`data/migration.py` 新增迁移版本（重建表而非字段转换）
- `config/level_config.json` / `body_level_config.json` 按十进制境界体系重写（**修炼升级曲线本次不动**，但实现时必须走 config 可调，为后续调整预留）
- 装备/功法/心法配置词条化改造（附带被动与触发技能、领悟概率系数）
- 战力公式、PvE/Boss 数值生成随新属性体系重校准
