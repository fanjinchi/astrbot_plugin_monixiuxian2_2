# Design: worldview-bible

## Context

见 proposal.md。内容层填充在即，需要一个唯一事实来源统一文案基调。本 design 不定技术方案（无代码），只定义 bible 文档的**结构、写作规则与待决问题**，供后续探索对话填充。

## Goals / Non-Goals

**Goals:**

- 定义 `design_docs/world-bible.md` 的章节骨架与每章写作要求
- 明确"bible 写到多细"的粒度标准：细到能让内容作者（人或 AI）不追问就能写出互相一致的物品描述/事件文案
- 列出必须在本变更内回答的叙事决策（见 Open Questions 中标记 **阻塞性** 的条目）

**Non-Goals:**

- 不写具体物品/功法/宗门条目（那是后续内容变更的活）
- 不定数值（数值归 `current-design-report.md` 与 content-design 管线）
- 不为第二季（化神+）留钩子或预埋内容
- 不改任何 config JSON / CSV

## Decisions

### D1: bible 是一份扁平 Markdown，按"消费场景"组织章节

章节按"谁会来查它"划分，而不是按设定学分类：

1. **基调与文风**：一句话世界观电梯陈述；叙事视角（群聊文字游戏，第三人称"你"）；玩梗尺度（合欢宗保留所要求的边界：允许谐音梗/欢乐向门派梗，禁止出戏的现代词进入物品描述正文——梗放描述末尾或彩蛋位）
2. **地理**：下界地图（至少命名 5-8 个区域，与现有秘境/历练路线对齐：青云山、落日峡谷、万妖洞、玄冰地宫、上古遗迹等已在地名必须收编）
3. **势力**：正邪格局；现有青云门、合欢宗的定位收编；第一季规划 4-5 个宗门的空缺位留给内容变更填，但 bible 定"每个宗门必须绑定一条路线取向/一种玩法幻想"的规则
4. **修炼体系叙事化**：灵修/体修的世界观解释（体修何以为体、灵修借何力）；境界的叙事含义（练气→元婴每境一句话）；寿元、突破失败、身死道消的叙事处理
5. **命名规范**：武器/功法/心法/丹药/敌人/秘境的命名模式与用词库（品级词：凡/灵/玄/地/天 等的使用规则），附"禁用词"清单
6. **既有内容收编清单**：列出 config 中所有已存在的名字（物品、宗门、地名、妖兽），标注每条"收编为正史 / 改名 / 待删"——bible 不能无视存量

### D2: 粒度标准 = "可消费性测试"

每章写完后自检：给一个虚构任务（"写一把元婴期灵修飞剑的描述"），只看 bible 能否不追问地完成。不能则说明该章粒度不够。

### D3: 双路线叙事差异是 bible 的硬需求，不是可选项

路线基调已定（见 proposal），bible 必须给出叙事解释，因为它会反过来约束技能/心法命名与描述（例：体修技能名应偏"肉身/气血/山岳"语系，灵修偏"符箓/飞剑/借法"语系）。

## Risks / Trade-offs

- [bible 写得过大，内容填充永远开不了工] → 目标两页以内、六章为限；粒度以 D2 的可消费性测试为准，超过即删
- [与存量 config 文案冲突] → D1 第 6 章的收编清单逐条处理，冲突以 bible 为准，改名动作列入 tasks
- [玩梗尺度模糊导致文案风格漂移] → 第 1 章必须给出至少 3 个"合格/不合格"对照示例

## Open Questions

以下留给后续探索对话（建议以 `/openspec-explore worldview-bible` 继续），均为**阻塞性**——不回答则 bible 无法完成：

1. 世界有没有名字？大陆/位面叫什么？
2. 正邪对立的烈度：是你死我活还是竞争共存？魔修势力是否在第一季可见？
3. "上界"的存在是否被下界修士知晓？（影响化神以上内容的措辞，即使第一季不开放）
4. 妖兽/妖域的智慧程度：纯野兽 vs 有妖修文明？（影响敌人命名池与 boss 名的写法）
5. 玩家扮演的是什么：无名散修起步？轮回转世？（影响新手引导类文案口吻）
