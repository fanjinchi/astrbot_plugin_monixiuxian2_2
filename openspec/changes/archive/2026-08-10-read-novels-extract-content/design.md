# Design: 读修仙小说原文提取内容素材

## Context

- 见 proposal.md - Why：网络调研只得到笼统概述，需要小说**原文**才能提取具体素材（宗门情节、道具、功法神通）。
- 现状：`design_docs/novel-research/` 已有 2 本概述笔记（01-fanren-xiuxian-chuan.md、02-xian-ni.md）；其余 8 本尚未调研。
- 本项目玩法 80+ 指令，spec 已将其归纳为 9 个提取维度（境界突破、宗门情节、道具法宝、功法神通、丹药灵药、地名势力、事件奇遇、战斗描写、人物关系）。
- 工具环境：`fetch_content`（网页正文抓取）、`bash`（curl/批量下载）、`compress`（上下文压缩）；约束：design_docs 新资料需登记 README。

## Goals / Non-Goals

**Goals**
- 建立可重复的"定位免费源 → 获取全文 → 分批阅读 → 按 9 维度提取 → 写 extract-*.md + 登记"流水线。
- 10 本小说各产出一份具体素材记录，素材以"名称 + 章节 + 情节摘要 + 玩法映射"为最小单元。

**Non-Goals**
- 不改游戏代码、不产出最终 `config/*.json` 数值（素材后续另走 content-design 流程）。
- 不做全书逐字精读（不现实，见决策 D2）。
- 不在仓库中分发小说原文（版权），extract 文件只保留短引用。

## Decisions

### D1: 小说源获取策略（多级备选）
**实测结论（2026-08，browser-harness + curl 验证）：**
- ❌ 不可达/假站：biquge.co、xbiquge.la、biquge5200.cc、biquge.com.cn、bxwx.org、ddxs.com、zwdu.com、69shu.com、52bqg.com（连接超时）；hetushu.com、69shuba.com（403 反爬）；**bqg128.com 返回 200 但为域名停放页（for sale）——假站需警惕**
- ✅ 真站可用：**quanben.io（全本小说网）**——实测《凡人修仙传》全本 2446 章完整可读（URL 模式 `quanben.io/n/<slug>/list.html`，章节 `/<n>.html`，目录页为折叠列表）；**b520.cc**、**biquge.cx**——真实笔趣阁站（书页 URL 模式 `b520.cc/{num}_{num}/`，站内搜索不可用需外部找书号）；**52shuku.net**（凡人修仙传 2059 章完结版）；17k.com / qidian.com / jjwxc.net 正版站可达
- **首选**：quanben.io（已实测全本可读）；GitHub 文本仓库 / 公开 txt 资源（`curl` 整本下载，无广告无翻页）
- **备选**：b520.cc / biquge.cx（需先外部搜书号）；52shuku.net；69shuba（403 带浏览器会话重试）
- **兜底**：书目替换（从 10 本清单内换一本）
- 每本记录实际来源 URL 与抓取日期。

### D2: 阅读深度分档（关键决策）
10 本小说均为 2000+ 章长篇，按用户要求分两档：
- **全本档（3 本：凡人修仙传、仙逆、遮天）**：**持续阅读直至读完**——每次读一批章节（如 50-150 章），立即增量写入 extract 文件并更新进度标记，compress 该批原文；跨会话从进度标记续读，直到全书读完（无 gap）。默认选择理由：设定最经典完整（凡人流/逆天流/大帝流各代表一系）、免费源可得性高、已有概述笔记便于对照。**用户可调整书目**。
- **部分档（7 本：诛仙、一念永恒、我师兄实在太稳健了、大奉打更人、诡秘之主、道诡异仙、佛本是道）**：精选关键章节精读（各卷开头 + 关键剧情节点）+ **网络搜索补充总结各维度设定**，每条素材标注来源（原文章节 vs 网络调研）。
- 两档均可用关键词 grep 定位高价值章节（如"丹药""功法""秘境""雷劫""神木"），弥补遗漏。
- *备选方案*：全 10 本每本采样 30-60 章——用户否决（覆盖不了后期新设定），弃用。

### D3: 上下文管理协议（全本档专用）
阅读原文会产生大量文本，按以下节奏控制：
- 每批抓取/阅读一批章节（50-150 章）→ 立即提取 → **增量写入 extract 文件（含进度头更新）** → **compress 该批原文**（原文属于"已消费内容"）。
- extract 文件是唯一留存 + 跨会话进度载体，原文不保留在上下文中（用户可自行查阅原站）。
- 每本完成后 compress 该本的抓取过程消息。

### D4: 文件组织
- 输出：`design_docs/novel-research/extract-<slug>.md`，slug：`fanren / xianni / zhetian / zhuxian / yinian / wenjian / dafeng / guimi / daogui / foben`。
- 模板（与 spec 一致）：头部（书名/作者/来源URL/抓取日期/**已读至第 X 章 / 共 Y 章**）→ 按 9 维度分节 → 每项条目（名称/章节/情节摘要/玩法映射/原文引用）→ 部分档额外标注每项来源（原文章节/网络调研）→ 覆盖 gap 说明（仅部分档）。
- 既有概述笔记（01/02）保留为"设定总览"，与 extract 素材库互补；README 资料清单新增登记 extract 文件。

### D5: 素材与玩法系统的映射约定
每条素材的"玩法映射"字段使用固定标签集合（来自 spec 9 维度对应的游戏系统），如 `突破`、`宗门`、`装备`、`功法`、`丹药`、`秘境`、`历练`、`战报`、`Boss`、`传承`、`经济`、`洞天/灵田`、`社交`、`事件文本`。素材最终去向（config 或展示文本）由后续 content-design 决定，extract 阶段只负责"原料"。

## Risks / Trade-offs

- [小说源不可用/被墙/下架] → 多镜像备选；全部失败则换书目并记录替换原因（spec 场景已覆盖）
- [反爬/验证码拦截抓取] → 换源；fetch_content 失败时改用 bash + curl 带 UA 重试
- [采样漏掉关键剧情] → 关键词 grep 兜底 + 记录 gap；用户可指定补充章节继续提取
- [上下文膨胀导致任务中断] → D3 压缩协议：每批写完即压，extract 文件为持久载体
- [版权风险] → 不存储/分发全文，extract 仅含短引用（<100 字/条），注明来源

## Migration Plan

- 无代码迁移。产出流程：逐本完成（获取→阅读→提取→登记），10 本全部完成后 README 汇总。
- 回滚：删除对应 extract 文件与 README 登记行即可，无副作用。

## Open Questions

- **全本档 3 本书目为默认假设**（凡人修仙传、仙逆、遮天），用户可在 apply 前调整（如想全读其他书）；部分档 7 本清单相应跟随变化。
- 全本档若因版权找不到免费源，按 D1 兜底替换并记录（替换对象优先从部分档升档）。
