# Design: dual-route-identity

## Context

见 proposal.md。引擎现状：突破成功时固定 `气血+15`（`hp_growth_step`）+ 5 个战斗点按全局权重随机分配（`random_growth_step` + `growth_weights`，伤害0.6/身法0.25/迅捷0.15），见 `core/breakthrough_manager.py:202-209`。物品侧 `route_multiplier` 已在 `models.py:285` 生效（装备属性与心法被动均按路线乘算）。

## Goals / Non-Goals

**Goals:**

- 双路线有可体感的战斗身份差异，且满级面板差距 ≤ 个位数百分比
- 成长差异全部配置化，后续赛季（化神+段）只需续表
- 内容作者拿到明确的填写规则（三族归属、机制预算）

**Non-Goals:**

- 不改闪避/暴击等判定公式本身（40% 闪避上限等维持现状）
- 不重做玩家已有属性，不提供洗点（随机方差是 Q宠模式的既有特性，保留）
- 不做 max_level 封顶与内容填充（后续变更）

## Decisions

### D1: 成长表 = 「路线 × 境界段」二维配置 + 创角区间差异化（C1）

`game_config.json` 的 `skill_system.growth_by_route`（已落地，数值为**模拟校准定稿**）：

- 体修：`hp_step` [17,16,15,15]；练气段权重 伤害.55/身法.25/迅捷.20 → 元婴段 .46/.28/.26
- 灵修：`hp_step` [15,16,17,17]；练气段 .52/.22/.26 → 元婴段 .62/.16/.22
- 数组下标 = 大境界序号（0=练气…3=元婴），每段权重和恒为 1；与十进制境界体系对齐，后续赛季开放新境界时追加数组元素即可
- 突破管理器按 `player.cultivation_type` + 当前大境界取行（升境界的突破按原段结算）；配置缺失时回退到现有全局 `growth_weights`（向后兼容）
- **C1（创角）**：灵修创角迅捷区间 5-15 → **10-18**（`cultivation_manager.py`），迅捷身份从创角成立并对冲体修创角面板优势；体修创角区间不动（其前期身份的全部来源）

**校准结论**（`sim_route_matchup.py`，每格 3000 场，详见 `route-matchup-report.md`）：

- 体修胜率曲线：练气段 ~58%（创角面板差驱动，上限放宽至 62%）→ 筑基 ~52% → 金丹/元婴 ~50% 收敛，"初期略强、后期赶上"成立
- 满级期望面板：体修 气血763/伤害121/身法58/迅捷54/护甲6，灵修 745/124/47/57/0——气血差 ~2%，灵修伤害反超、迅捷领先
- **关键发现 1**：迅捷是行动经济（P(出手)=速度占比），收益近似线性，大迅捷差会摧毁平衡——初版锚点（灵修迅捷+15）体修胜率仅 22~40%。灵修的迅捷身份只能是"快一点"
- **关键发现 2**：创角随机区间的路线差（体修伤害+9.5/气血+40/护甲+6.5）比成长表任何调整都大，是前期平衡的主导项；成长表负责"收敛"而非"制造"差异
- 已知残留：L30 armed 格灵修胜率 56% 是占位武器（青云镇山剑护甲 80）压扁伤害差的伪影，武器梯度在 season1-content 填充后需复验
- 调参工具：`sweep_route_growth.py`（一次性扫参脚本，保留供后续赛季续表时复用）

### D2: 机制预算表（内容规范，非代码闸门）

| 境界段 | 解锁机制 | 天然受益者 |
|---|---|---|
| 练气 | 纯面板 + 直接增伤/减伤触发技 | 体修（面板略高） |
| 筑基 | +暴击/吸血/连击等数值变种 | 拉平过渡 |
| 金丹 | +状态效果（灼烧/减甲/眩晕）、条件触发 | 灵修（迅捷=触发次数多） |
| 元婴 | +必杀技、复合条件、机制联动 | 灵修完全体 |

- 机制对两条路线**均等解锁**；路线差异在构成比例与风味：灵修向内容机制占比高（≈7成），体修向内容以数值型为主但保留肉身风味机制（≈4成：反震/护体罡气/浴血/受击反击类），保证双方后期都有可玩的 build 深度
- 前期保留 1-2 件灵修向「迅捷面板件」作为身份信物，避免灵修前期裸奔
- 该表写入 content-design authoring 规则；`validate_budget.py` 增加检查：练气段物品 MUST NOT 声明必杀技，筑基及以下 MUST NOT 声明状态效果

### D3: 三族系数规范

- 通用件：双边 1.0（允许 ±0.05 内的风味偏差）
- 路线向件：优势方 1.2~1.4 / 劣势方 **0.5~0.7**——两族之间对称（体修向/灵修向互为镜像），件内奖小于罚，跨路线使用要"肉疼"以体现路线专属性（2026-08-27 用户 review 修订，原为对称 1.1~1.3/0.7~0.9）
- 通用件占商店/掉落的大头（目标 ≥50%），惩罚加重后该占比成为硬约束：任何路线玩家都有稳定可用的装备流

### D4: 校准方式

新增 `design_docs/attribute-growth/sim_route_matchup.py`（复用 `sim_xiuxian_turns.py` 的 CombatEngine 引导与武器解析；后者场景 A/B 因 level_config 公式化已过时，不修）：同等级 体修 vs 灵修 对抗，期望值属性 + 同档最强武器（系数按通用件 1.0）。通过标准：各里程碑胜率 50:50±5pt；练气段体修可因创角面板差上浮，上限 62%（C1 后实测 ~58%）。校准报告归档 `route-matchup-report.md`（已完成，见 D1 校准结论）。

## Risks / Trade-offs

- [成长随机方差叠加路线权重后，个体玩家可能偏离路线画像（如灵修连roll身法）] → 已定调：接受方差，"练歪了"视为风味（Q宠模式既有特性）；补救手段走内容向——后续设计加属性的丹药让玩家自行修正，不做洗点/保底机制
- [体修闪避优势 + 闪避差值制公式，可能在同路线内战或被高身法敌人克制时失真] → 校准时额外跑 体修vs体修、玩家vs高身法妖兽 场景；必要时第二季再调 dodge 公式参数
- [机制预算表靠规范约束而非代码闸门，可能被违规填写] → validate_budget 加检查兜底；review 时抽查
