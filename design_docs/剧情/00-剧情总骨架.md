> **归属**：tier-1 高频文案写作（`openspec/changes/season-1-tier1-copywriting`）
> **用途**：批量写作前的"结构图纸"。评审通过后按册（01-04）填充剧本，最终校验后灌入 `content-design/copy_variants.csv`
> **文风基线**：`design_docs/world-bible.md`（§1.2 三拍 / §1.3 梗尺度 / §4 词汇 / §5 用词禁忌），口味 = **按 bible 标准**（用户已确认）
> **素材库**：`design_docs/novel-research/`（10 本精读 + 跨书模板，细节不够时再上网补）
> **范围边界**：本骨架覆盖 4 域（breakthrough / cultivation / combat / adventure_event）+ fortune 域掉落 flavor（tasks 2.4 归入**本 change**：weapon_drop / heart_method_drop / pill_drop 场景的掉落 flavor 变体，见 §1.1 末）。legacy_encounter 不属本 change，不写、不动。秘境说明与扩充规划整体延后（§1.5），不属本期。

## 0. 六条总纲（每条变体都必须过）

1. **三拍结构**：动作 → 画面 → 结果；单条 1~3 行；第三人称"你"；说书人口吻。**正经句先行；幽默按 tone 档落位**——`正经+冷幽默`=正/冷约各半、幽默写进正文（台词/动作/收尾三选一）；`玩梗灰`=括号彩蛋位；`正经`=无幽默补丁（§1.2/§1.3）。
2. **数值句锁定**：凡含 `{var}` 的数值句（伤害/恢复/修为/气血）句式必须与现有模板一致，修辞只加在句首铺垫；**剧本不得自造任何数值承诺**（具体灵石数、经验值、概率一律不写）。
3. **变体即格子**：每条变体 = CSV 一行 = (domain, scene, level_band, state, route, variant_no, text, tone_tier, narrative_status, note)。骨架定义了每个格子的值域，填充阶段只做"抄剧本进格子"。
4. **意象守则**：一物一名（§5.4）；禁词零容忍（§5.3）；凡/灵/玄/地/天品级词只做冠词不进正文（§5.1）；连缀称号（仙王/仙尊级）禁用。
5. **结局开放（剧情线兼容）**：通用事件文案不得写死封闭结局——"彻底了结/永世不灭/此后再无"这类句式会把未来主线剧情链的接续口焊死。每条事件保留"事情还有后续可能"的开放性，未来剧情链可以把现有事件当作剧情节拍（beat）复用。
6. **幕表同步**：文案中的世界状态宣言必须与 `season-1-outline.md` §1 幕表对齐——练气不得预支金丹幕叙事（如传承之地现世是元婴幕事件）；复苏阶段/妖乱强度/宗门对散修态度按所在段位取值（样张 8.7 蛮州妖狼即按练气幕"低阶妖兽躁动"取值）。

段位分桶：`通用 / 练气（筑基前夕）/ 筑基（金丹前夕）/ 金丹（元婴前夕）`，按**突破目标境界**落桶；灵/体双路线分轨。

**双路线差异必须显形**：境界名两路同表，但突破/修炼画面必须用各自语系写出差异——灵修文用"丹田/灵台/神识/元神"，体修文用"气血/皮膜/筋骨/烘炉"；同段位两条线不得只改句式不换意象。

**fortune 域（tasks 2.4 归入本 change）· 3 场景 · 预算 ≈8 条**：掉落 flavor 变体（机缘得物画面），纯 flavor 不承载数值/品级承诺（品级词只做冠词不进正文）；scene 键=weapon_drop / heart_method_drop / pill_drop（narrative_config fortune 节，变量 {name}、{rank}、{items}）。段位通用即可，tone 正经为主（捡漏题材可玩梗灰，与 trade_windfall 一梗不二用）。

**三语系**（§5.5）：体修用肉身/气血/山岳；灵修用符箓/飞剑/借法/罡风；通用段用天地/山水/风雨/日月等中性自然词。一域之内语系不得混搭。

**禁词速查 + 替换建议**：系统→(删)/等级→境界/属性→根基/装备→法宝、器物/技能→术法、神通/buff→法门加持/CD→(删)/经验→修为/任务→差事、历练/冷却→(删)；超规格词（最强/无敌/唯一）+ 现代梗一律删。

## 6. 文风速查（写每条前过一眼）

- **tone_tier 四值**：`正经`=青云/金刚/通用默认；`正经+冷幽默`=天机；`玩梗灰`=万毒/血魔/捡漏题材（克制）；`平淡`=工程句（带条件的提示类）。
- **tone 构成规则**：`正经+冷幽默` 档 = 每事件正经/冷幽默约各半（11 条 ≈ 5-6 条冷），冷幽默**写进正文**（台词/动作/收尾三选一），**禁止 `（…）` 括号补丁**；`玩梗灰` 档 = 括号彩蛋位专属（正文即笑点，括号仅额外点心），一梗不二用、彩蛋须玩家能看懂（外传梗不写）；`正经` 档无幽默补丁。
- **擦边尺度**（§1.3b）：暗示不直白、点缀不喧宾、不物化；禁词表照常生效。
- **行数**：单条 1~3 行（≤2 句为宜）；上限以 `lint_narrative.py` 的 domain 长度参数为准（写作时跑 lint 实测）。

## 7. 变量白名单与句式锁定（tasks 1.4 的对照底稿）

| domain / scene | 可用 `{var}` | 句式要求 |
|---|---|---|
| breakthrough / success, death, survive | {next_level_name}、{rate_info} 等 | 数值行由突破系统拼接追加；剧本句可承载成长占位，**不得自造数值** |
| breakthrough / revive | — | 回生丹复活画面，不承诺次数 |
| combat / 全部 | {defender_name}、{attacker_name}、{actor}、{target}、{dmg}、{heal}、{counter_dmg} 等 | 伤害/恢复句尾必须保留"造成 X 点伤害/恢复 X 点气血"句型的数字呈现；修辞只加句首 |
| cultivation / retreat_settlement | {time_str}、{fairyland_line}、{gained_exp}、{exceed_msg}、{current_exp} | {time_str} 处保持"闭关 X 日"语感 |
