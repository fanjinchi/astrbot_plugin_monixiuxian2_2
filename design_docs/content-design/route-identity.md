# 双路线定位与内容设计规范（灵修 / 体修）

> 2026-08-27 定稿（openspec change `dual-route-identity`）。**填充任何武器/功法/心法内容前必读**。
> 本文是路线平衡设计的长期事实来源；openspec 变更归档后以本文为准。
> 数值校准复跑入口：`uv run python design_docs/attribute-growth/sim_route_matchup.py`。

---

## 1. 路线身份（一句话）

- **体修**：肉身成圣。创角面板即强（伤害/气血/护甲），身法（闪避）全程占优，技能偏数值型 + 肉身风味机制（反震/护体/浴血/受击反击）。前期强、后期被追平。
- **灵修**：借力打力。迅捷（出手频次）从创角起领先，伤害后期反超，技能偏机制型（控制/连击/必杀）。前期平淡、后期发力。

## 2. 数值定稿（第一季：练气→元婴，Lv1-40）

### 创角随机区间（`core/cultivation_manager.py`）

| 属性 | 灵修 | 体修 |
|---|---|---|
| 伤害 | 8-18 | 15-30 |
| 身法 | 5-15 | 3-10 |
| 迅捷 | **10-18** | 5-12 |
| 气血 | 90-130 | 120-180 |
| 护甲 | 0 | 3-10 |

### 突破成长表（`config/game_config.json` → `skill_system.growth_by_route`）

每段权重和恒为 1，战斗点 5 点/次突破两路线相等；升境界的突破按**原境界段**结算。

| 境界段 | 体修 hp步长 / 伤害 / 身法 / 迅捷 | 灵修 hp步长 / 伤害 / 身法 / 迅捷 |
|---|---|---|
| 练气 | 17 / .55 / .25 / .20 | 15 / .52 / .22 / .26 |
| 筑基 | 16 / .52 / .26 / .22 | 16 / .55 / .20 / .25 |
| 金丹 | 15 / .49 / .27 / .24 | 17 / .58 / .18 / .24 |
| 元婴 | 15 / .46 / .28 / .26 | 17 / .62 / .16 / .22 |

满级期望面板（含创角）：体修 气血763/伤害121/身法58/迅捷54/护甲6；灵修 气血745/伤害124/身法47/迅捷57/护甲0。

### 校准结果（3000 场/格，`route-matchup-report.md`）

体修胜率：练气 ~58%（上限 62%）→ 筑基 ~52% → 金丹/元婴 ~50%。

### 两条血泪教训（调数值前先看）

1. **迅捷是行动经济**：P(出手) = 自己速度 / 双方速度和，收益近线性。灵修迅捷领先一旦超过"一点"（满级 +6 左右），体修胜率崩盘（实测 22-40%）。**任何"让灵修快很多"的想法都会破坏平衡。**
2. **创角区间是前期平衡的主导项**：体修创角 +9.5 伤害/+40 气血/+6.5 护甲，比成长表能调的一切都大。前期体修优势是创角给的，成长表的职责是**收敛**差距，不是制造差距。

## 3. 内容三族规范（武器/功法/心法通用）

`route_mult_ling` / `route_mult_ti` 是**逐件物品的身份标识**，不承担全局平衡职责：

| 族 | 系数 | 占比目标 | 用途 |
|---|---|---|---|
| 通用件 | 双边 1.0（允许 ±0.05 风味偏差） | ≥50% | 商店/掉落主力，任何路线都可用 |
| 体修向件 | 体修 1.2~1.4 / 灵修 **0.5~0.7** | 补强 | 重剑/拳套/肉身类心法 |
| 灵修向件 | 灵修 1.2~1.4 / 体修 **0.5~0.7** | 补强 | 飞剑/符箓/借法类心法 |

- **劣势方惩罚显著大于优势方加成**（0.5~0.7 vs 1.2~1.4）：跨路线捡装备要感到"肉疼"，路线向件才有专属性；两族之间对称（体修向与灵修向互为镜像），件内不对称（奖小于罚）。
- **不要**给通用件做"体修略高"之类的倾斜——体修前期优势已由创角+机制预算表（§4）表达，通用件倾斜会让灵修前期双重挨打。
- 惩罚加重后，通用件 ≥50% 的占比目标成为**硬约束**：任何路线玩家在商店/掉落/机缘里都必须有稳定可用的装备流，设计新档位时先保通用件数量再填路线向件。
- 前期保留 1-2 件灵修向"迅捷面板件"（加速度的轻剑等）作为身份信物，避免灵修前期裸奔。

## 4. 机制预算表（按境界段解锁复杂度）

机制对两条路线**均等解锁**；路线差异在构成比例与风味，不在准入。

| 境界段 | 解锁机制 | 天然受益者 |
|---|---|---|
| 练气 (L1-9) | 纯面板 + 直接增伤/减伤类触发技 | 体修（面板略高） |
| 筑基 (L10-19) | +暴击/吸血/连击等数值变种 | 过渡拉平 |
| 金丹 (L20-29) | +状态效果（灼烧/减甲/眩晕）、条件触发 | 灵修（迅捷=触发次数多） |
| 元婴 (L30-40) | +必杀技、复合条件、机制联动 | 灵修完全体 |

- 机器校验：`validate_budget.py` 的 `check_weapon_mechanics_band` 强制武器挂载触发技分段合规（练气段仅直接增伤/减伤、筑基及以下禁状态效果）；skills.csv 无等级列，功法侧的必杀/状态段位纪律经**心法的 required_level_index 门禁**落实（技能池挂在心法上），fill 时人工核对、review 抽查。
- 构成比例参考：灵修向内容机制型 ≈7 成；体修向内容数值型为主但保留 ≈4 成肉身风味机制（反震/护体罡气/浴血/擒拿反击），保证双方后期都有 build 深度。
- 设计理由：机制复杂度随境界解锁本身就是进阶仪式感；且前期机制全是面板向 → 天然利好体修的创角面板，后期百分比/状态/必杀 → 天然利好灵修的迅捷与触发频率，**路线弧线由内容类型分布自动形成，无需系数倾斜**。

## 5. 填充内容时的检查清单

1. 世界观/命名/文案基调 → `design_docs/world-bible.md`（唯一事实来源）
2. 这件内容属于哪一族？系数按 §3 对称取值
3. `required_level_index` 落在哪个境界段？机制是否符合 §4 预算表
4. 数值预算 → 本目录 `README.md` §3 + `validate_budget.py`
5. 改动成长表/创角区间后 → 复跑 `sim_route_matchup.py` 校验收口
